# 5 — Producing a tearsheet with `feat report`

> **Scenario.** You've done the work — read the business, valued it, put it
> against peers. Now someone wants "the one-pager." `feat report` assembles
> profile, trends, key ratios, forensic scores and a valuation summary
> (with the FMP reference-DCF cross-check) into a single self-contained
> document you can paste into a memo or email.

## A markdown brief to stdout

```sh
$ feat report AAPL
```

```markdown

- Net income: `▁▂▃▄▄▆▆▇▇█`  (latest 97.00B)
```

It's plain markdown, so it renders anywhere — GitHub, a wiki, a pull request,
a Slack message. Because it's text, it also diffs cleanly: commit last
quarter's and this quarter's tearsheets and `git diff` shows exactly what
moved.

## Choose the valuation model

The valuation section defaults to `dcf-fcff`; point it at whatever fits the
name:

```sh
$ feat report KO  --model ddm
$ feat report JPM --model residual-income
```

If the chosen model can't run (say a DCF on a name with negative base FCFF),
the tearsheet doesn't fail — the valuation section prints
_"Valuation unavailable: …"_ with the reason, and the profile, ratios and
forensic sections are still produced. A partial tearsheet beats no tearsheet.

## Write files, including HTML

`--out` writes to disk instead of stdout; `--format html` wraps the same
content in a minimal, dependency-free, self-contained HTML page:

```sh
$ feat report AAPL --format html --out ./tearsheets/
feat: wrote /home/you/tearsheets/aapl.html
```

For **multiple tickers**, point `--out` at a directory and `feat` writes one
file per name (`aapl.md`, `msft.md`, …), creating the directory tree as
needed:

```sh
$ cat tech.txt | feat report - --out ./tearsheets/
feat: wrote /home/you/tearsheets/aapl.md
feat: wrote /home/you/tearsheets/msft.md
...
```

`feat` guards the obvious footgun: if you give several tickers but an `--out`
that's an existing *file*, it refuses (exit code `2`) rather than overwrite
one name with the next.

## Getting the most out of it

- **Batch a whole book into a folder** in one shot:
  ```sh
  $ cat holdings.txt | feat report - --format html --out ./q3-tearsheets/
  ```
- **Freeze the numbers** for a document that will be reviewed next week:
  ```sh
  $ feat report AAPL --model dcf-fcff --snapshot --out ./memo/
  ```
  Warm the cache once, then everyone regenerating the tearsheet gets the
  identical figures — no "why does mine say something different?"
- **Version your coverage.** Commit the markdown tearsheets to a repo and let
  history do the tracking; each quarter's regeneration is a reviewable diff.

## Interpreting, honestly

A tearsheet is a *summary of work already done*, not a substitute for it. It
deliberately shows one valuation model and the latest fiscal year — enough to
brief a decision, not enough to make one. When the one-pager raises a
question, drop back to `analyze` for the full ratio history and `value` for
the sensitivity, scenarios and Monte Carlo behind that single fair-value
line. The footer says it plainly: every figure is traceable, and it's not
investment advice.
